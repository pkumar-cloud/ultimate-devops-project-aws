# Ingress and Ingress Controller

## Ingress
- Ingress -> incoming traffic, Egress -> Outgoing traffic.
- Kubernetes has a resource of kind ingress, which can help you define the routing rules for your incoming traffic to the cluster.
- Ingress controller reads the ingress object/resource (e.g. ingress.YAML) file understands what is the exact requirement and creates load balancer accordingly.
- If you're using service type load balancer, CCM is creating the load balancer for you. Instead, if you keep the service type as cluster IP or node port, and if you create **ingress resource** for that particular service (e.g. frontend service here), Ingress controller reads that YAML file and
  according to the rules defined in the ingress file, it creates the load balancer.
- Till now creating the pod through deployment (for autohealing and scaling) and you were creating a service resource (for service discovery part). Now you are also creating ingress resource so that you can customize the incoming traffic to your pod. (Ingress -> Service -> PDO (Deployment))
- Ingress resource is only created for the service that needs external access e.g. frontendproxy svc here, thus for frontendproxy svc, we will create service, deployment and ingress all three.

## Ingress Controller (CRD)
-  Kubernetes is not opinionated about the ingress controller i.e. Kubernetes does not say that this is the ingress controller, or this is the code for the ingress controller that you have to deploy. Because Kubernetes want to provide you the flexibility of using any load balancer that you want.
-  Thus, Kubernetes provides the standard interface/API for Ingress, but leaves the implementation and choice of controller to LB provider (e.g. NGINX, Traefik, HAProxy, Kong, AWS (ALB, NLB), GKE, F5 ). It not available by default on the cluster.
-  E.g. If you want to use nginx load balancer, then you need to deploy nginx ingress controller. if Kong -> Kong ingress controller etc..
-  If you just deploy ingress resource for your service, nothing happens until and unless you have ingress controller deployed.
-  The ingress controller watches the ingress resource, it will read the YAML file, understand the rules you want to configure and will create the load balancer.
-  For this project, we will deploy a ALB ingress controller then  will create ingress resource for frontendproxy service, once the ALB controller reads the ingress resource, it creates the load balancer. Whatever domain name we provide in the ingress resource, ALB controller will tell the load balancer that only allow traffic from this particular domain name.

### Deploy ALB Ingress Controller:
- ALB controller is deployed as a pod in K8S cluster, then how it can create an ALB/ELB which is out of Kubernetes cluster ?
- To create any resource in AWS, you need to assign a IAM role to the service, or if you are a user, you need to have IAM user and both the user or role should have the policies. Only then you can create any resource in AWS.
- Every pod has a service account. We will create IAM role and assign policy with required permissions to the IAM role. And as a next step we will connect the ALB pod service account with IAM role using IAM OIDC provider.
